今天使用 opencode 的免费额度用到了上限，这么多天来的第一次。并不是说消耗的 Token 多，结果就会更好，恰恰相反，今天的 Vibe Coding 很失败，几乎没有完成任何预定的任务。总结一下原因：需求太多，需要联动修改的地方太多。

我的焦虑不是没有 token 用，我可以充值，**钱可以解决 token 不足的问题，但解决不了如何控制大模型编写代码的思路问题。** 可能有朋友会说，是模型能力不行。不不不，现在不是大模型刚开始的 1.0 时代了，现在的大模型都挺能打的。打个比方，国外的大模型好比是 RTX 5090 32G，性能没得说；国内的大模型怎么也顶得上 1060 8G，厉害点的顶个 3060 12G 也差不多了。如果你的需求是打植物大战僵尸、玩玩扫雷，用 5090 会更强吗？对于普通人尤其是没有编程基础的人，需求基本上不会很复杂，用哪个模型结果都差不多。

其实写过多年代码的程序员都知道，无论有没有 AI，刚接触编程的人都在做同一件事：重复造轮子。以前是 ctrl+c，现在是靠 AI 复刻。你想到的需求，可能早就被人实现过了，如果没被实现，大概率是因为没什么价值。

有一个无限猴子定理：

> 如果让一只猴子随机敲击键盘，只要时间无限长，它必然能敲出一份完美的、可编译运行的《GTA6》源码。

按这个理论来说，如果给一个人无限的 token 和无限的时间，那人理论上也能做出市面上的任何 APP 和游戏。但现实是残酷的，我们没有无限 token 也没有无限的时间，只有有限的 token 和有限的时间，在这个条件下编写提示词、拆分需求、反复验证。

我很怀念刚接触编程的时候，那时用文本编辑器写代码，有代码提示都觉得这玩意真高级！本子上密密麻麻地记着各种软件的配置命令和各种语言的常用方法。后来开始用笔记软件创建自己的知识库，写博客分享经验，在 QQ 群里因一个方法一个属性激烈讨论。有时候写一个功能多些的应用，花个一年半载都算快的。而且那时候开源氛围也很好，只要你的项目有搞头，大家都跃跃欲试，分工也很细致。怀念啊！

我记得我当时想用 Python 的 GUI 做一些小应用，为了熟练编写 Tk 代码，花了整整一个多月学习，基本上能熟练地构建出小型应用的 GUI 原型。后来为了用 Web 构建应用，开始接触 Vue、React 等前端框架，包括后来的 Tailwind 样式库，手写代码都很熟练。

忘了具体是从什么时候开始的了，基本上不再手工编写代码了。写代码和写文章不一样——你可以不用 AI 写文章，写错字、句子不通顺，大概率都能顺着理解出意思。但代码不行，写错一个符号、字母、甚至多一个空格都不行。所以，作家可以写到老，自己检查错误，有点小错误也无妨。但程序员能吗？30 岁以后，人的体力和注意力都开始走下坡路，学习能力也开始下降，这也是为什么程序员吃年轻饭，而艺术家越老越有经验越有名气。无奈，Vibe Coding 也是老年程序员的唯一出路——至少在编写代码的效率、review 的准确率、程序设计的协助性上，给了老年程序员一个新的希望。

代码的全新编写方式，是我以前不敢想象的。如果现在有人想学编程，我一定会推荐他用 AI 编写代码，但我会告诉他：你一定要知道 AI 给你写的代码是干什么用的，如果看不懂，你就无法控制整个项目的全局。是你在编写代码，AI 只是帮你写而已，而不是许愿。至少现在的 AI 还不是神，即便它成了神，也会像神一样，根本管不过来那么多许愿的人。

最近发现极简主义的博客主题也是不错，首先精简动效、样式，功能等，这样代码量下来了，大模型处理起来也快，功能的实现也会很快，毕竟代码少了，出现bug的几率也会减少，所以，我这段时间又要开始砍代码了，大概率会砍到bear极简主题那种样式。对了，我今天还把鱼缸里的鱼分开了，希望他们各自安好，好好活着做条快了的小鱼。
